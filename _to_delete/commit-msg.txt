Phase 1: turn notes into flashcards

The generation prompt is the deliverable here; the function around it is
plumbing. functions/src/prompt.ts holds the system prompt and the strict
JSON schema, with the five non-negotiables from DESIGN.md 4.1 written out
as rules plus four worked examples.

- onNoteCreated fires on the NAMED database and is deployed in
  europe-west3, where the database lives. Eventarc requires this; the HTTP
  functions stay in europe-west1.
- Card ids are deterministic ({noteId}_{i}) so at-least-once redelivery
  overwrites rather than duplicating, and a shorter retry sweeps orphans.
- The >=1 card guarantee is enforced in code, not in the prompt: a strict
  JSON schema cannot express a minimum array length, and a silently dropped
  capture is the one failure this app cannot afford.
- dryRunCards generates and writes nothing, and takes a promptOverride, so
  a whole eval sweep costs one deploy instead of one per wording.
- Library shows cards under their source note with inline edit and delete.
  A failed note offers "Try again", which re-captures the text as a new
  note because the trigger only fires on creation.
- firebase.json gains a predeploy hook: npm ci installs but never compiles,
  and the CLI reads the gitignored functions/lib/index.js.
- The predeploy hook calls node_modules/.bin/tsc directly rather than
  npm run build: the Firebase CLI spawns predeploy through a
  non-interactive shell that does not source nvm, so npm there was an old
  system version that crashed without a TTY.
